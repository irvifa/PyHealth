# ProtoECGNet on PTB-XL: reproduction and equal-budget contrastive test

CS 598 Deep Learning for Healthcare (Fall 2026) final project, Irvi Aini
(iaini2). This folder reproduces ProtoECGNet (Sethi et al., MLHC 2025) on
PTB-XL 1.0.3 with PyHealth, and tests the paper's contrastive-loss claim with
multiple seeds and an equal tuning budget.

- **Library code:** the PTB-XL multi-label task and the `ProtoECGNet` model
  were merged upstream in
  [sunlabuiuc/PyHealth#1323](https://github.com/sunlabuiuc/PyHealth/pull/1323).
- **This folder:** the experiment scripts, raw results and write-ups.
- **Pinned code:** every result here was produced with PyHealth at commit
  `2d51ace` (branch `protoecgnet-ptbxl` on this fork). Upstream master has
  changed since, so install from this branch to reproduce the numbers exactly.

## Results

Rhythm branch (16 labels), fold-10 macro AUROC, mean ± sd over 6 seeds
(0–2 on a MacBook Pro M4 Pro with MPS, 3–5 on a Kaggle Tesla T4).

| Variant | Ours | Paper (Table 1) |
|---|---|---|
| Black-box (1D ResNet) | 0.9368 ± 0.0034 | 0.9403 |
| ProtoECGNet, no contrastive | 0.9308 ± 0.0105 | 0.8903 |
| ProtoECGNet, contrastive | 0.9281 ± 0.0062 | 0.9064 |
| Gain (contrastive − no contrastive) | −0.0026 ± 0.0131 | +0.0161 |

The black-box baseline matches the paper. The contrastive gain does not
reproduce: the gain is negative in 5 of 6 seeds, and weighted AUROC is lower
in 6 of 6. Details, per-seed bootstrap CIs and the rare-label analysis are in
[`runs/rhythm_all/results.md`](runs/rhythm_all/results.md).

## Reproducing

All commands run from the repository root.

### 1. Get the code

```bash
git clone -b protoecgnet-reproduction https://github.com/irvifa/PyHealth.git
cd PyHealth
```

### 2. Create the environment

PyHealth needs Python 3.12 or 3.13. With [uv](https://docs.astral.sh/uv/):

```bash
uv venv -p 3.12 .venv
uv pip install --python .venv/bin/python -e ".[ptbxl]"
```

The `ptbxl` extra installs `wfdb`, which is needed to read the waveforms.

Optionally, run the model's unit tests (synthetic data, under a minute):

```bash
uv pip install --python .venv/bin/python pytest
.venv/bin/python -m pytest tests/core/test_protoecgnet.py -q
```

### 3. Download PTB-XL 1.0.3

PTB-XL is open access on PhysioNet (about 1.7 GB zipped):

```bash
mkdir -p ~/data && cd ~/data
curl -L -o ptbxl.zip https://physionet.org/static/published-projects/ptb-xl/ptb-xl-a-large-publicly-available-electrocardiography-dataset-1.0.3.zip
unzip -q ptbxl.zip
export PTBXL_ROOT=~/data/ptb-xl-a-large-publicly-available-electrocardiography-dataset-1.0.3
ls "$PTBXL_ROOT"/ptbxl_database.csv "$PTBXL_ROOT"/records100 >/dev/null && echo ok
cd -
```

### 4. Smoke test (synthetic data, about a minute)

```bash
.venv/bin/python experiments/protoecgnet/branch_seed_sweep.py --synthetic \
    --seeds 0 --out-dir experiments/protoecgnet/runs/smoke
```

This checks that the full pipeline runs. Its AUROC numbers are meaningless.

### 5. Full run

The settings used for every reported result: rhythm branch, 20 epochs for the
`feature_extractor` and `joint` stages, 15 classifier epochs after projection,
lr 1e-3, batch 32, 5 global prototypes per label, folds 1–8 / 9 / 10 for
train / val / test.

**MacBook (Apple silicon), seeds 0–2, about 53 minutes:**

```bash
PTBXL_ROOT="$PTBXL_ROOT" bash experiments/protoecgnet/run_mac.sh
```

The script uses `caffeinate` to keep the Mac awake. Set `DEVICE=cpu`,
`SEEDS=…` or `EPOCHS=…` to override the defaults.

**Linux with an NVIDIA GPU, seeds 3–5:**

```bash
.venv/bin/python experiments/protoecgnet/branch_seed_sweep.py \
    --root "$PTBXL_ROOT" --branch rhythm --seeds 3,4,5 --epochs 20 \
    --device cuda --cache-dir ~/.cache/pyhealth-ptbxl \
    --out-dir experiments/protoecgnet/runs/rhythm_gpu
```

**Kaggle (free T4), seeds 3–5, about 1 hour:**

1. Create a notebook and set Accelerator to *GPU T4 x2* (or P100) and
   Internet to *On*. Do not choose a TPU.
2. Paste each block of `experiments/protoecgnet/kaggle_cells.txt` into its own
   code cell, without the `=== CELL n ===` banner lines, and run them in order.
   Cell 1 installs PyHealth at the pinned commit (5–10 minutes). Cell 2
   downloads PTB-XL. Cell 4 is the smoke test. Cell 5 is the full run.
3. Download `/kaggle/working/results_rhythm.zip` from the Output panel.

If you edit `branch_seed_sweep.py`, regenerate the cells with
`python experiments/protoecgnet/build_kaggle.py`.

Runs are resumable. If a run stops, rerun the same command with the same
`--out-dir`; finished (seed, variant) pairs are skipped.

### 6. Merge machines and summarize

The merged 6-seed table was produced with:

```bash
cd experiments/protoecgnet/runs
mkdir -p rhythm_kaggle rhythm_all/preds
unzip -o ~/Downloads/results_rhythm.zip -d rhythm_kaggle
cat rhythm_mac/results.jsonl rhythm_kaggle/results.jsonl > rhythm_all/results.jsonl
cp rhythm_mac/preds/*.npz rhythm_kaggle/preds/*.npz rhythm_all/preds/
cp rhythm_mac/config.json rhythm_all/
cd -
.venv/bin/python experiments/protoecgnet/branch_seed_sweep.py --branch rhythm \
    --out-dir experiments/protoecgnet/runs/rhythm_all --summarize-only
```

This writes `runs/rhythm_all/summary.md`. It contains mean ± sd per variant,
the paired gain per seed with a bootstrap 95% CI, and every run.

## Notes

- **AUROC is computed from logits, not probabilities.** Right after prototype
  projection, the rhythm branch's logits are around −100 to −300. Float32
  sigmoid then underflows to exactly 0, and AUROC from probabilities reads
  0.5. Logits rank the same way, so AUROC from logits is the correct metric.
  The 15-epoch classifier stage then lets the last layer recover (see
  `runs/rhythm_mac/mac_results.md`).
- **Paired comparison.** For each seed, the black-box, no-contrastive
  (`lam_cnrst=0`) and contrastive (`lam_cnrst=300`) variants share one
  `feature_extractor` checkpoint and the same data order. Only the
  contrastive weight differs.
- **Results vary slightly by device.** MPS and CUDA runs of the same seed
  aren't bit-identical. Expect black-box macro AUROC of about 0.93–0.94 on
  any machine.
